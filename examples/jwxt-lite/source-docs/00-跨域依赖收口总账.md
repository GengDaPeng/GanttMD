## 1. 文档定位

本文档用于汇总当前各模块跨域清单中的剩余问题，判断每个问题当前应如何收口。

本文档不是新的产品基线，不替代模块规格、字段字典、接口清单、专项设计或数据库设计。它只回答：

- 哪些跨域问题已经被顶层基线、底座契约或模块主规格关闭。
- 哪些问题需要落入某个模块的接口清单或字段字典。
- 哪些问题需要拆成专项设计。
- 哪些问题需要回写 `01 / 02 / 03 / 05 / 06` 顶层基线。
- 哪些问题应留到考勤中心、统计与审计、课程与课表等后续模块启动时再确认。

`00-跨域决策回写与模块校准清单.md` 继续作为 2026-05-07 跨域 9 项决策的落地索引。本文档承接的是模块规格补齐后产生的“当前问题总账”。两者不互相替代。

## 3. 使用规则

1. 各模块跨域清单仍保留在各自目录，记录本模块视角的依赖。
2. 本文档只做汇总、分流和关闭判断，不在这里重新定义业务规则。
3. 已关闭项应回写对应模块清单，把状态改为“已关闭”或“已由某文档承接”。
4. 待接口项应进入对应模块 `接口清单.md`；没有接口清单的模块应先补最小接口清单。
5. 待专项项应新建专项设计，不应继续散落在模块跨域清单里。
6. 待顶层回写项必须先判断落点：`01` 业务边界、`02` 阶段范围、`03` 技术约束、`05` 前后端总体设计、`06` 核心数据模型。

## 4. 总体判断

当前已经完成一轮主规格补齐的模块：

- 审批中心
- 系统设置
- 学生管理
- 班级管理
- 教师管理
- 组织、权限与账号

当前主要缺口不再是“有没有主规格”，而是：

1. 组织权限账号主规格、字段字典、接口清单和 `权限范围与ScopeResolver专项.md` 均已进入主线。
2. `ScopeResolver` 已形成输入事实、输出契约、规则合并、缓存失效、审计和失败兜底口径；组织管理接口清单已承接核心输出契约，`06` / 数据库专项对象落点仍需确认。
3. 审批、考勤、通知、调度、跨域任务、数据库落表之间的运行机制还未形成专项设计。
4. `02-V1范围说明.md` 的设备接入口径已回修，后续设备型号、字段、部署和验收由设备专项承接。
5. 考勤中心完整形态主规格第一版已形成，字段字典、接口清单、安全到校方案和请假草稿已完成初稿；本轮进入对端确认、接口契约 / 错误码校准和专项分流。
6. 后端基础结构、Prisma 迁移跑道、本地依赖、本地一键启动与基础 CI 已落地；工程实现前的主要缺口转为第一条“安全到校”纵切方案。
7. 学生管理审查已通过 PR 合并；`registration_ownership`、`study_relationship`、`StudentBorrowStudyRecord` 的对象分层已回写 `06-核心数据模型基线.md` V2.6，外部上报编码映射仍需后续专项承接。
