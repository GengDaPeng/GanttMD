# 新项目初始化指南

本文说明一个刚开始的项目如何接入 GanttMD。

## 第一步：创建目录

在项目根目录创建：

```text
.ganttmd/
  config.yaml
  followups.md
  modules/
tools/
  ganttmd/
```

把当前可视化页面复制到：

```text
tools/ganttmd/index.html
```

如果项目暂时不想放 `tools/`，也可以先放在：

```text
.ganttmd/index.html
```

但长期推荐 `tools/ganttmd/index.html`，让 `.ganttmd/` 专注保存任务数据。

## 第二步：写 config.yaml

最小示例：

```yaml
project:
  name: 示例项目

milestones:
  - id: M1
    name: 项目骨架建立
    status: in_progress
    description: 明确需求边界、工程骨架和最小闭环

  - id: M2
    name: 第一条业务闭环
    status: backlog
    description: 完成一条可验收的端到端业务链路

  - id: M3
    name: 扩展与治理
    status: backlog
    description: 补齐质量、权限、审计和部署治理
```

里程碑建议控制在 3-5 个。不要把每个模块都写成里程碑。

如果项目已有完整路线图，可以把暂时没有任务的里程碑也写入 `config.yaml`。页面会显示为 `0 任务 · 未拆解`，表示路线图存在但还没有拆到执行任务。

## 第三步：创建模块任务文件

按工作主线创建模块文件，例如：

```text
.ganttmd/modules/
  product.md
  backend.md
  frontend.md
  qa.md
```

模块文件不是代码模块的一比一映射，而是任务推进主线。一个模块文件里建议先放 3-8 个任务。

## 第四步：写第一批任务

任务使用 fenced code block：

````markdown
### S-BE-01 后端工程骨架专项设计

```ganttmd-task
id: S-BE-01
title: 后端工程骨架专项设计
status: todo
dependencies: []
milestone: M1
track: backend
module: foundation
priority: P0
source_docs: [docs/需求说明.md]
next_action: 明确后端目录、模块边界和启动入口
acceptance: [目录结构确定, 本地启动路径明确, 后续实现任务可承接]
evidence: []
```

补充说明写在任务块外面。
````

任务块内放结构化字段。任务块外可以写人类可读说明。

## 第五步：写 AGENTS.md

把 `docs/Agent协作规则模板.md` 的内容复制到项目根目录 `AGENTS.md`，再按项目实际情况改路径和限制。

Agent 不会天然知道 GanttMD 的存在，必须通过 `AGENTS.md` 明确告诉它：

- 任务文件在哪里。
- 怎么判断可领取任务。
- 怎么领取。
- 怎么完成。
- 什么情况下不能改任务状态。

## 第六步：打开页面验证

打开：

```text
tools/ganttmd/index.html
```

选择项目根目录，检查：

- 任务是否被读取。
- 里程碑是否显示。
- 执行视角是否能看到可执行任务。
- 依赖阻塞是否符合预期。
- 健康检查是否提示缺字段。
- Follow-up 视图是否能正常显示 `.ganttmd/followups.md`。

## 起步建议

新项目第一天不要写太细。

推荐起步规模：

- 3 个里程碑。
- 2-4 个模块文件。
- 10-20 个任务。
- 每个任务只写必要字段。

等项目真实推进一轮后，再补 `next_action`、`acceptance`、`source_docs` 的细节。
