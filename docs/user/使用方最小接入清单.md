# 使用方最小接入清单

本文档面向“使用 GanttMD 的项目”，不是 GanttMD 开发者。

以 `jwxt` 这类业务项目为例，GanttMD 应作为项目根目录下的 `.ganttmd/` 任务状态层存在，并跟随 Git 管理。

`.ganttmd/` 是动态任务状态的唯一真相源。不要在项目里长期并行维护另一套“项目进度文档”；已有总控待办、模块推进清单等动态进度材料，应逐步迁入 `.ganttmd/tasks/*.md`，原文档只保留静态说明、路线背景或 GanttMD 入口。

## 推荐目录

```text
your-project/
  AGENTS.md
  .ganttmd/                # 所有 GanttMD 相关文件都在这一个目录内
    index.html             # 看板页面（从 GanttMD 仓库 examples/minimal/.ganttmd/ 复制）
    rules.js               # 共享规则模块（同上；必须与 index.html 同目录）
    config.yaml
    followups.md
    tasks/
      main.md
  docs/
    ...正式需求、设计、接口、测试文档...
```

**核心原则**：一切关于看板的事情，从 `.ganttmd/` 这一个入口进。复制、卸载、升级都只动它一个目录。

## 哪些内容放进 `.ganttmd/`

`.ganttmd/` 放：

- `index.html` + `rules.js`：可视化看板与共享规则（从 GanttMD 仓库 `examples/minimal/.ganttmd/` 复制）。
- `config.yaml`：项目、里程碑和视图配置。
- `tasks/*.md`：任务、状态、依赖、证据链和验收摘要。
- `followups.md`：后续事项、用户裁决、延期复核、外部等待和风险项。

这些文件都应该提交到 Git。原因是：

- Agent 需要读取它们来决定下一步。
- 人类负责人需要审查任务状态变更。
- PR 可以看到任务状态、证据链和 follow-up 的变更历史。
- validate / CI 可以检查它们是否符合规则。

## 哪些内容不要放进 `.ganttmd/`

不要把正式正文搬进 `.ganttmd/`：

- 产品需求正文。
- 技术方案正文。
- 数据模型正文。
- 模块规格正文。
- 接口清单正文。
- 测试规范正文。
- PR 评论流水。
- 长篇 AI 讨论记录。

这些内容继续放在项目原来的 `docs/`、PR 或其他正式位置。`.ganttmd/` 通过 `source_docs`、`source_pr`、`source_rr`、`source_commit` 引用它们。

`source_docs` 不是另一套进度来源，只是任务的依据链接。它引用的是需求、设计、接口、数据模型、测试规范或 PR 证据；动态进度仍然只写在 `.ganttmd/`。

## Agent 需要读什么

使用方项目的 Agent 只需要从项目自己的 `AGENTS.md` 入口开始。

典型读取路径：

```text
AGENTS.md
.ganttmd/config.yaml
相关的 .ganttmd/tasks/*.md 与 followups.md 条目
当前任务列出的 source_docs
```

Agent 不应每次全量阅读所有任务文件，也不应默认读取 GanttMD 仓库里的设计讨论文档。它应先用任务 ID、状态、依赖或页面/CLI 推荐定位相关任务，再读取必要的任务文件和来源文档。

## 最小接入步骤

1. 在使用方项目根目录创建 `.ganttmd/`。
2. 从 GanttMD 仓库的 `examples/minimal/.ganttmd/` 复制 `index.html` 和 `rules.js` 到 `.ganttmd/`。
3. 创建 `.ganttmd/config.yaml`。
4. 创建 `.ganttmd/tasks/main.md`。
5. 创建 `.ganttmd/followups.md`。
6. 将 `docs/Agent协作规则模板.md` 合并到使用方项目 `AGENTS.md`。
7. 用浏览器打开 `.ganttmd/index.html`，点"选择目录"，选项目根目录或 `.ganttmd/` 自己。
8. 如安装了 GanttMD CLI，运行：

```bash
npm run validate -- .
```

## 最低成功标准

- 页面能读取任务。
- 里程碑能显示。
- 执行视角能看到下一步任务。
- 风险视角能看到阻塞和健康检查。
- Follow-up 视图能显示清单。
- validate 没有 warning。
