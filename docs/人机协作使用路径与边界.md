# AI Agent 协作建议

本文说明在有 AI Agent 参与的软件项目中，如何让 GanttMD 看板保持可信。

## 核心建议

`.ganttmd/` 是任务状态数据，不是临时聊天记录。为了避免多个 Agent 随意改状态，建议团队指定一个任务分发 Agent 或看板维护者负责结构性维护：

- 创建、拆分、取消和关闭任务。
- 调整依赖、里程碑、主线和领域。
- 清理 follow-up。
- 定期运行 `ganttmd validate`。

执行 Agent 只处理当前任务范围：

- 领取已存在任务。
- 更新当前任务状态。
- 补充 `evidence`、`verification`、`review_status`。
- 主控关闭任务时补充 `completed_branch`，记录完成分支。
- 维护当前任务 checklist。
- 追加 `status: open` 的 follow-up。

这个分工不是强制要求。单人项目可以由开发者直接维护；多 Agent 项目建议采用这个模型，保证看板和实际项目状态一致。

## 真相源边界

GanttMD 保存：

- 任务 ID、标题、状态和依赖。
- 里程碑、主线和领域。
- 证据链、验证方式和复核状态。
- 阻塞原因和 follow-up。
- 执行批次、分支和 checklist。

GanttMD 不保存：

- 完整需求正文。
- 完整技术设计。
- 接口文档正文。
- 测试规范正文。
- 长篇讨论记录。

这些内容应留在项目原来的文档、PR 或 issue 中，GanttMD 只通过 `source_docs`、`source_pr`、`source_rr`、`source_comment`、`source_url`、`source_commit` 引用。

## 推荐工作流

1. 看板维护者创建或拆分任务。
2. 执行 Agent 读取 `AGENTS.md`、`.ganttmd/config.yaml` 和相关任务文件。
3. 执行 Agent 领取依赖已完成的任务。
4. 执行过程中维护 checklist，并补充证据。
5. 任务完成后补 `evidence` 和 `verification`。
6. 需要复核的任务进入 `review`。
7. 看板维护者清理 follow-up，并决定是否转成正式任务。

## 完成态建议

`done` 应至少满足：

- 有 `evidence`。
- 工程类任务有 `verification`。
- 需要复核的任务有 `review_status`。
- 剩余事项已登记为 follow-up 或新任务。

如果已经有产出但还在等待复核，使用 `status: review`。

## 多分支并行

如果多个分支或 worktree 同时推进，可以用 `.ganttmd/runs.md` 记录：

- 当前批次 ID。
- 分支名。
- 负责人或 Agent。
- 本批次涉及的任务。
- 当前正在处理的任务。

`runs.md` 是运行态记录，不是新的任务真相源。正式任务仍在 `.ganttmd/tasks/*.md`。

## 提交前检查

在提交 `.ganttmd/` 改动前运行：

```bash
ganttmd validate
ganttmd doctor
```

CI 中也可以使用：

```yaml
- name: Validate GanttMD
  run: ganttmd validate
```
