# 项目总控看板

## 1. 文档定位

本文档是 `jwxt` 项目的系统级调度入口，用于让项目负责人快速判断四条主线当前做到哪里、卡在哪里、下一步该找哪个线程推进。

本文档不替代产品基线、技术基线、数据模型基线、模块规格、专项设计或实现文档；也不替代模块开发总控。

系统总调度只管：

- 四大主线节奏：模块规格、后端工程、前端工程、设备接入。
- 横切质量门：基线回写、数据库对象落点、权限范围、跨域依赖、端到端闭环。
- 关键阻塞和下一步系统级动作。
- 已完成事项的可追踪记录。

系统总调度不管：

- 不直接给具体模块代理派任务。
- 不维护模块内部的详细写作顺序。
- 不替代模块开发总控判断某个模块文档是否可合并。
- 不把设备调研、旧实现、前端原型直接上升为基线结论。

模块内部任务分发、模块规格推进顺序、模块代理协调和模块审查节奏，由模块开发总控负责。系统总调度只接收模块总控输出的状态、阻塞、质量门结果和需要回写的稳定结论。

```text
→ M3 / M4 / M5 依次形成可运行系统
```

偏航检查：

- 如果一个任务只是在补局部文档，但不能推进 M1-M5 的任一质量门，应先暂缓。
- 如果模块内部任务绕过模块开发总控直接进入系统总调度，应退回模块总控。
- 如果前端、后端或设备实现没有对应基线 / 模块规格 / 专项输入，应先补质量门，不直接开工。
- 如果设备 SDK 资料、前端原型或旧实现与当前基线冲突，以基线为准；需要改变基线时先做基线回写判断。
- 如果连续推进两个以上文档任务后仍没有靠近 M2 工程跑道或 M5 纵切，应重新审查节奏。

- 每次系统级状态变化，优先更新本文档的“四大主线进度树”和“完成记录”。
- 每次新增系统级任务，必须写明所属里程碑；没有里程碑归属的任务不得进入当前优先队列。
- 树状任务需要临时说明、风险提示、特殊边界或等待原因时，使用缩进的 `> 说明：...` 写在对应任务项下方，不覆盖任务本身。
- 模块内部任务不写入本文档，只记录模块质量门、阻塞和模块总控反馈。
- 若模块总控输出稳定结论，系统总调度判断其落点：顶层基线、专项设计、数据库规范、前端专项、后端工程或设备专项。
- 若实现、调研或前端原型与基线冲突，以基线为准；需要变更基线时先进入质量门判断。
- 历史讨论、废弃方案和过期状态不在本文档长期保留；完成事项进入“完成记录”，详细过程进入对应正式文档或历史归档。
